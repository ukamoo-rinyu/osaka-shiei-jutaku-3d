# 閲覧者からの報告を受けて直す流れ

```
閲覧者：check.html で確認 →「結果を出力して報告」→ コピー → Googleフォームに貼り付けて送信
管理者：フォームの回答を見る → 内容をClaudeに貼り付けて「反映して」と頼む
Claude：マスタCSV・3Dマップ・確認ページを更新してプッシュ
```

## 1. Googleフォームを用意する（最初の1回だけ）

1. Googleフォームを新しく作る（タイトル例：「大阪市営住宅3Dマップ 確認結果の報告」）
2. 質問を作る
   - **確認結果**（段落・必須）… 確認ページからコピーした内容を貼り付けてもらう欄
   - **気づいたこと**（段落・任意）… 自由記述
   - **連絡先**（記述式・任意）… 問い合わせが必要なとき用
3. 右上の「送信」→ リンク（🔗）でURLをコピー（`https://docs.google.com/forms/d/e/…/viewform` か `https://forms.gle/…`）
4. そのURLをClaudeに渡して「確認ページにフォームのURLを設定して」と頼む
   （Claudeは `python3 tools/build_check_page.py 'フォームのURL'` を実行し、確認ページ check.html の「Googleフォームを開く」ボタンに設定します）

報告の入口は確認ページ（check.html）に一本化しています。3Dマップ（index.html）で住棟や住宅を選ぶと、その住宅を開いた確認ページへのボタンが出ます。

URLを設定するまでは、確認ページの「Googleフォームを開く」ボタンは表示されません（CSV保存は使えます）。

設定済みのフォーム：https://docs.google.com/forms/d/e/1FAIpQLScGGzhssu_Ax0esjxqsZFrZebnoe-seR5kVGPS9JKaOQl3Xrw/viewform

## 2. 報告の形

確認ページから出力される内容は次のような形です。

```
# 大阪市営住宅3Dマップ 確認結果
# データ: 2026-10-06 / 出力: 2026-10-20 21:05 / 3件
区,住宅,住棟,報告の種類,PLATEAU建物ID,建物の中心緯度,建物の中心経度,位置_緯度,位置_経度,階高m,階数,高さm,範囲（経度 緯度;…）,メモ
中央区,上町住宅,,問題なし,,,,,,,,,,
住之江区,中加賀屋住宅,中加賀屋住宅３号館,建物を修正,bldg_xxxx bldg_yyyy,34.6… 34.6…,135.4… 135.4…,,,,,,,
住之江区,中加賀屋住宅,中加賀屋住宅１４号館,一覧にない住棟を追加,bldg_zzzz,34.6…,135.4…,,,,,,,2025年完成
住吉区,南住吉第１住宅,,敷地範囲,,,,,,,,,135.5007837 34.6025369;135.5026073 34.6025369;…,
住吉区,南住吉第１住宅,南住吉第１住宅１号館,3Dモデル（建物範囲）,,,,,,2.9,8,23.2,135.5013308 34.6017364;135.5020602 34.6018364;…,
```

| 報告の種類 | 意味 |
|---|---|
| 問題なし | その住宅は表示どおりで合っている |
| 住宅へのメモ | 住宅全体についてのメモ |
| 建物を修正 | 号館の建物を付け替えた（PLATEAU建物IDが新しい対応。複数あれば空白区切り） |
| 位置だけ指定 | PLATEAUに建物がないので位置だけ指定した |
| 建物なし | 号館の建物をすべて外した（位置も指定なし） |
| 解体済み・見当たらない | その号館はもう無い |
| 一覧にない住棟を追加 | 一覧にない住棟がある（建物IDか位置つき） |
| メモのみ | 号館へのメモだけ |
| 建て替え前（解体） | 建て替えで解体された号館。メモに「建て替え後：新しい住棟の名前」 |
| 建て替え後（新しい住棟） | 建て替わった新しい住棟（建物IDか位置か3Dモデルつき）。メモに「建て替え前：号館名」（複数の号館が1つにまとまったときは `・` 区切り） |
| 3Dモデル（建物範囲） | PLATEAUに建物がない住棟の直方体モデル。「範囲」が建物の形（角の経度・緯度を `;` 区切り、閉じていない）、高さ＝階高×階数（階数が空なら高さも空） |
| 敷地範囲 | 住宅の敷地の範囲（「範囲」の形式は上と同じ） |

3Dモデルと敷地範囲は、どちらか片方だけの報告もあります。「一覧にない住棟を追加」の行に階高・階数・範囲が入っていれば、追加した住棟の3Dモデルです。

## 3. Claudeへの頼み方（例）

> 3Dマップの確認報告が届いたので反映してください。内容は次のとおりです。
> （フォームの回答「確認結果」をそのまま貼り付け。複数件あれば続けて貼る）

Claudeは次を行います。

1. 報告の中身を一覧にして、取り込む・取り込まないの判断を管理者に確認する
   （航空写真と見比べて明らかにおかしいものはその旨を伝える）
2. `data/shiei_jutaku_master.csv` と `data/shiei_jutaku_flood_risk.csv` を更新
   （建物IDの付け替え、解体済みの削除、追加住棟の行の追加、「確認状況」の更新）
   3Dモデルの報告は「位置の種類」を描いた形（直方体）にし、高さ・階数を入れる
   建て替えは、建て替え前の号館の行を消し、建て替え後の住棟の行を足す（建設年度・戸数は大阪市の一覧で確認）
3. 3Dマップ `index.html` に埋め込まれたデータを同じ内容に更新
   （3Dモデルは、いま半透明の箱で出している住棟を、報告の形・高さの箱に置き換える。
   敷地範囲は、住宅の点線（同じ住宅名の住棟を囲んだ目安）を報告の範囲に置き換える）
4. `python3 tools/build_check_page.py` で確認ページ `check.html` を作り直す
5. コミットしてプッシュ

## 確認ページのしくみ（メモ）

- `check.html` は `tools/build_check_page.py` が `tools/check_page_template.html` から作るファイル。直接は編集しない
- 周りのPLATEAU建物（約4万3千棟）は、もともと `tools/danchi_check.html` に入っていたもの
- 閲覧者の入力はブラウザ（localStorage）に保存されるだけで、どこにも送信されない。送られるのはフォームに貼り付けた内容だけ
- 入力は建物IDで保存しているので、確認ページを作り直しても閲覧者の入力は消えない
